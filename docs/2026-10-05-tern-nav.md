# herdr-style navigation in Tern

## Goal

Bring herdr's navigation keys to Tern 0.4.5 on the Mac window, for panes on the Mac and on the remote host `mini`:

- `ctrl+h/j/k/l` move between nvim splits first, then Tern panes at the split edge (herdr `navigate.py` plus `vim-tmux-navigator.lua`).
- `alt+shift+n/p` and `alt+shift+j/k` cycle sessions; `alt+shift+1..9` jump to session N (herdr `next_workspace`, `previous_workspace`, `switch_workspace`).
- `ctrl+alt+1..9` focus agent N (herdr `focus_agent`).

## Constraints

- Keys stay in `tern/keys.json`; the plugin registers commands only, no default `keys`.
- Window half only. The Mac links it; `mini` needs no plugin.
- No fallbacks, shims, suppressions or code comments.

## Facts the design rests on

Verified on Tern 0.4.5 in an isolated instance (`TERN_CONFIG_DIR`, `TERN_DAEMON_SOCKET` under `/tmp`, `tern --control`) unless noted.

- A `keybinds` array never consults a plugin command's `available`; `available` only filters palette rows. The command itself has to branch.
- The window's `PaneInfo.program` is the foreground command the shell integration reports (`cat` for `cat -v`, `omp` for omp on `mini`).
- `cx:run(pane, "\x08")` reaches the program as `^H`.
- `tern focus BLOCK`, run inside a pane or outside, moves the window's focus.
- `tern ls --json` gives each tab's layout as `{"Split": {"axis": "Row"|"Column", "ratio", "a", "b"}}` / `{"Leaf": id}`; `Row` puts `a` left of `b`, `Column` puts `a` above `b`. Its `cols`/`rows` go stale; ratios don't.
- A `mini` pane has `TERN_PANE` and `TERN_PANE_SOCKET`, an empty `TERN_WINDOW_KEY`, and `~/.local/bin/tern` on the interactive `PATH`; `tern ls --json` there lists `mini`'s sessions from its own daemon.

Rejected channels for "nvim reached its edge, move Tern focus":

- `tern open /tern-nav/<dir>` into `tern.route.open`: fires locally, but from a `mini` pane the daemon opened a file block itself and the Mac route never ran.
- `tern open <scheme>://…` into `tern.route.link`: the CLI treats it as a relative file path.
- Pane title changes into the window `title` event: Oh My Zsh retitles every command, and back-to-back changes arrived out of order.

## Design

### `tern/nav/plugin.toml`, `tern/nav/window.luau` (new)

Plugin id `nav`, window entry only. Commands, all `plugin.nav.<id>`:

| Id | Behavior |
| --- | --- |
| `left`, `down`, `up`, `right` | Focused pane's `program` basename is `view`, `fzf`, `ssh`, `mosh`, `tmux`, `herdr` or matches `^l?n?vim?x?$`: `cx:run(pane, byte)` with `\x08`, `\x0a`, `\x0b`, `\x0c`. Otherwise `cx:action("focus_pane:<dir>")`. |
| `next_session`, `previous_session` | Index of `cx.sessions:current().id` in `cx.sessions:list()`, step with wrap-around, `cx.sessions:switch(id)`. |
| `session_1`..`session_9` | `cx.sessions:switch` to the Nth entry of `cx.sessions:list()`; nothing past the end. |
| `agent_1`..`agent_9` | `cx.layout:focus` the Nth entry of `cx.agents:list()`; nothing past the end. |

Sessions switch by id: the local and `mini` sessions are both named `Default`.

### `nvim/.config/nvim/lua/plugins/vim-tmux-navigator.lua`

At a split edge (`wincmd` left the window unchanged), herdr keeps precedence, then Tern when `$TERN_PANE` is set: `tern ls --json`, find the tab whose layout holds `$TERN_PANE`, lay the tree out in the unit square from the ratios, pick the pane whose edge touches the current one on that side with the largest shared span, `tern focus <id>`. The CLI talks to the daemon of the machine nvim runs on, which owns that session, so the same code serves Mac and `mini` panes. Both CLI calls wait at most 1 s and raise with the exit code and stderr on failure; a pane that is floating or detached has no tab layout, so the key does nothing there.

### `tern/keys.json`

`ctrl+h/j/k/l` → `plugin.nav.left/down/up/right`; `ctrl+a>ctrl+l` → `text:\x0c` keeps clear-screen reachable; `alt+shift+n`/`alt+shift+j` → `plugin.nav.next_session`; `alt+shift+p`/`alt+shift+k` → `plugin.nav.previous_session`; `alt+shift+digit_N` → `plugin.nav.session_N`; `ctrl+alt+digit_N` → `plugin.nav.agent_N`.

### `justfile`

`tern-plugin` links `tern/nav` with `tern plugin link` on the machine showing the window. `tern-keys` depends on it, because `keys.json` binds `plugin.nav.*` and a user bind to a missing plugin action replaces the lower layers with nothing.

### README

Document the plugin, the recipe, the new keys and the limits below.

## Limits

- Detection follows the command the shell reported. nvim started by another program (`git commit`, lazygit), launched behind a `VAR=value` prefix (Tern reports `PATH=… nvim` as the program), or fzf inside a zsh widget (`ctrl+r`, `ctrl+t`) isn't seen, so the key moves Tern focus there.
- ctrl+h/j/k/l no longer reach shells or agents: readline `ctrl+h`/`ctrl+k` and omp's `ctrl+j`/`ctrl+k` move focus instead, as under herdr. `ctrl+a>ctrl+l` clears the screen.
- A pane whose program exited but stays open (`exited` set) moves focus instead of forwarding.
- `agent_N` follows `cx.agents:list()` order, which the docs don't specify.

## Verification

In the isolated instance with the worktree plugin linked and the merged keys:

1. Shell pane in a 3-pane tab: `ctrl+h/j/k/l` move focus as the built-in does. Passed.
2. `cat -v` pane (not a key owner): `ctrl+h` moves focus. Passed.
3. nvim (worktree config) with a `:vsplit`, in the top-right Tern pane: `ctrl+l`/`ctrl+h` move between nvim splits with focus kept; `ctrl+l` at the right edge with no Tern pane there is a no-op; `ctrl+h` at the left edge focuses the left pane; `ctrl+j` at the bottom edge focuses the pane below. Passed.
4. Three sessions: `alt+shift+n`/`j` cycle with wrap, `alt+shift+p`/`k` reverse, `alt+shift+1..3` jump, `alt+shift+9` is a no-op. Passed.
5. omp in two other sessions: `ctrl+alt+1`/`2` focus each agent and switch sessions; `ctrl+alt+5` is a no-op. Passed.
6. On `mini`, headless nvim with a pane's `TERN_PANE`/`TERN_PANE_SOCKET`: `tern ls --json` decodes, the pane id round-trips through `tonumber` and `%d`, and a single-pane tab finds no neighbor. Passed.
7. nvim under a `tern` stub that fails `focus`: `ctrl+h` at the edge shows `E5108 … tern focus exited 1: stub refuses focus` and focus stays. Passed.
8. Live, on the Mac window: the user runs steps 1–5 in a `mini` tab after `git pull` there.
