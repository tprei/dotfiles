# Distill

Includes modified guidance from Impeccable. See [sources](SOURCES.md).

Remove obstacles, not necessary capability. Name the one primary outcome, decisions required, and the small part of the surface that delivers most value. Inventory repeated information, competing actions, visible advanced options, ornamental containers, noisy variation, extra steps, and dead variants. Decide what must remain visible, can be combined, or should be disclosed in context.

| Area | Change |
|---|---|
| Information architecture | Group related choices; expose one primary, few secondary, and clear entry to advanced actions. Remove duplicate facts, not the evidence users need. |
| Visual system | Try one family, three or four sizes, two or three weights, one or two decorative colors plus neutrals, and one spacing scale as a simplification exercise. Preserve functional status colors with non-color cues. |
| Layout | Flatten unnecessary nesting and chrome. Replace a grid of equivalent-looking panels with a clear reading path, or put secondary context inline. Align purposefully and use whitespace before frames. |
| Interaction | Consolidate duplicate actions and forms, try smart defaults, replace a modal with inline edit where available, and remove a step if it adds no decision or safeguard. Use progressive disclosure without hiding critical functions. |
| Language | Cut repeated intros and defaults that say nothing. Use concrete headings, short sentences, and active verbs. |
| Code | Remove unused styles, components and wrappers; consolidate only same-intent variants. Do not add an abstraction to disguise a local cleanup. |

Re-run the primary path; compare steps, time to locate action, accessibility, content cover, findability of advanced work, and actual performance where relevant. If removing a feature is in scope, document why, what access remains and how to monitor feedback. If complexity still belongs to the domain, represent it rather than hiding it. End with [polish](polish.md).
